01 · Source PDFs

File the source material once.

The source folder is the starting point for the local reference workflow. Keep the original PDFs there, use objective-aware filenames, and let the distiller create the AI-readable copies.

Put PDFs here

docs/AI-References/

Use the Weather AI project’s root folder as the reference point. Do not place source PDFs in local-agent/course/references/; that folder is for generated Markdown.

Use this filename shape

BLK-1-Unit-4-Obj-4c-PIREPS-and-TAFS.pdf

The important part is Obj-<code>. The distiller reads that code and assigns the generated reference to the matching evaluation objective.

Examples

  • BLK-1-Unit-4-Obj-4c-PIREPS-and-TAFS.pdf
  • AFMAN-15-124-Obj-3a.pdf
  • AFMAN-15-124-Obj-3b.pdf
  • AFMAN-15-124-Obj-5d.pdf

One source, multiple objectives

The current manifest gives each PDF one objective. If one source supports multiple objectives, make a clearly named copy for each code:

AFMAN-15-124-Obj-3a.pdf
AFMAN-15-124-Obj-3b.pdf

This keeps objective selection explicit and prevents a broad reference from being loaded into the wrong evaluation scope.

Before distilling

  1. Confirm the PDF is in docs/AI-References/.
  2. Confirm the filename contains Obj-<code>.
  3. For multiple objectives, create one copy per objective code.
  4. Continue to the Distiller guide.
